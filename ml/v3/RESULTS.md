# v3 ESP32-S3 추론 입력 전처리 결과

실행일: 2026-08-12

## 결론

gateway의 JSONL을 모델이 받을 수 있는 이벤트 단위 입력으로 변환하는 독립
파이프라인을 구현했다. 이는 새 분류 모델을 학습한 버전이 아니라, 저장 데이터와
향후 실시간 추론이 동일한 전처리를 사용하도록 만드는 버전이다.

현재 로컬 저장소에는 실제 수집 JSONL과 manifest가 없어서 실제 행동의 이벤트
경계가 맞는지는 아직 검증하지 못했다. 합성된 gateway 형식 데이터로 파싱,
이벤트 병합·분리, 잡음 제거와 64길이 입력 생성은 검증했다.

## 구현한 기능

- JSONL의 `timestampUtc`와 `raw` 읽기
- `RADAR_DADA`에서 다음 값 파싱
  - `wander`, `someone_threshold`, `someone`
  - `jitter`, `move_threshold`, `moving`
- 링크 로그의 RSSI와 패킷률을 다음 Radar 표본에 연결
- 짧은 `moving=false` 간격을 같은 이벤트로 병합
- 긴 정지 간격으로 서로 다른 이벤트 분리
- 이벤트 앞 1.5초와 뒤 2.0초 문맥 포함
- 한 표본짜리 움직임 잡음 기본 제외
- 가변 길이 이벤트를 64개 시간점으로 변환
- 상대 threshold 특징, 통계, 변화 속도, peak, 반복성과 전후 무활동 특징 생성
- gateway 라벨을 `walking / fall_suspected / other_motion / unknown`으로 변환
- 이벤트 JSONL, 특징 CSV, 품질 요약 JSON 출력

## 기본 이벤트 분할 설정

| 설정 | 기본값 | 의미 |
|---|---:|---|
| moving 사이 최대 간격 | 1.0초 | 이보다 가까운 moving 표본은 같은 이벤트로 병합 |
| 앞 문맥 | 1.5초 | 움직임 시작 전 신호 포함 |
| 뒤 문맥 | 2.0초 | 움직임 후 무활동 확인 |
| 최소 moving 표본 | 2개 | 한 표본짜리 움직임 오탐 제외 |
| 고정 입력 길이 | 64 | 모델이 받는 시계열 길이 |

이 값들은 모델 성능을 보고 고른 threshold가 아니다. 실제 수집 데이터로 이벤트
경계를 확인하기 전까지는 임시 기본값이다.

## 검증 결과

- v3 자동 테스트: **7개 통과**
- 기존 v0~v2 포함 전체 ML 자동 테스트: 최종 검증에서 함께 실행
- 빈 프로젝트 실행: 정상 종료 및 빈 출력 파일·요약 생성 확인
- 실제 로컬 세션: **0개**
- 실제 로컬 이벤트: **0개**

합성 검증에서 확인한 내용:

1. 실제 gateway와 같은 `RADAR_DADA` 필드 구조를 읽는다.
2. 중간에 짧은 정지가 들어간 moving 표본은 하나로 합쳐진다.
3. 긴 정지를 사이에 둔 moving 표본은 두 이벤트로 나뉜다.
4. 단일 moving 표본은 기본 설정에서 제외된다.
5. 이벤트마다 64길이 `jitter_relative` 등 추론 입력이 만들어진다.

## 실제 데이터가 생긴 뒤 통과 조건

v3는 다음 조건을 확인해야 최종 완료로 판단한다.

- 걷기와 생활 동작의 시작·종료가 육안으로 합리적으로 잘림
- manifest의 `eventAtUtc`가 해당 이벤트 주변에 위치
- 낙상 모의 동작을 한 표본 잡음으로 제거하지 않음
- 서로 다른 행동이 하나의 이벤트로 과도하게 합쳐지지 않음
- 세션별 파싱 손실과 긴 패킷 간격을 확인 가능
