# ESP32-S3 Wi-Fi CSI 공통 사용법

최종 확인일: 2026-08-17

이 문서는 운영체제와 무관한 보정, 화면 해석, 공간 프로필과 데이터 규칙을
설명한다. 실제 명령은 운영체제별 문서로 분리했다.

- [macOS 사용법](usage-macos.md)
- [Windows 사용법](usage-windows.md)

처음 설치하는 경우에는 [macOS 초기 세팅](setup-macos.md) 또는
[Windows 초기 세팅](setup-windows.md)을 먼저 따른다. 설치 버전과 경로는
[개발 환경](environment.md)을 참고한다.

## 문서 동기화 규칙

- 실행 명령, UI, 버튼, 메시지, 보정·수집 절차가 바뀌면 이 문서를 같은 변경에서 수정한다.
- 버전, 설치 경로, 하드웨어 역할 또는 아키텍처가 바뀌면 [개발 환경](environment.md)을 수정한다.
- 한 변경이 환경과 사용 흐름 모두에 영향을 주면 두 문서를 함께 수정한다.
- 코드·설정 변경은 사용자 승인 후 진행하며, 승인된 변경의 문서 동기화는 해당 작업에 포함한다.

## 1. 보드 연결

### TX 송신기

- 보조배터리 또는 USB 전원에 연결한다.
- 두 USB-C 단자 중 어느 쪽을 사용해도 전원 공급은 가능하다.
- 작은 빨간 LED는 전원 표시다. RGB LED가 켜지지 않아도 정상이다.
- 필요하면 전원 연결 후 `RST` 또는 `EN`을 한 번 누른다.
- 보조배터리의 자동 절전으로 빨간 LED가 꺼지지 않는지 확인한다.

### RX 수신기

- 보드의 `UART` USB-C 단자를 PC에 연결한다.
- Windows에서 `USB-Enhanced-SERIAL CH343`으로 표시되는 포트를 사용한다.
- TX와 RX는 USB 선으로 서로 연결하지 않는다.

## 2. 매일 시작하는 순서

1. TX에 전원을 공급하고 RX의 UART 포트를 PC에 연결한다.
2. 운영체제별 사용법의 `ports` 명령으로 RX 포트를 확인한다.
3. 운영체제별 모니터 스크립트를 실행한다.
4. 현재 공간 프로필과 채널을 확인하고 필요하면 적용한다.

공식 GUI, 프로젝트 모니터, 데이터 수집기와 시리얼 터미널은 같은 RX 포트를
동시에 사용할 수 없다. 명령은 [macOS 사용법](usage-macos.md) 또는
[Windows 사용법](usage-windows.md)을 참고한다.

## 3. 모니터 읽는 방법

GUI는 용도별로 세 탭을 사용한다.

- `실시간 모니터링`: 상태 카드, 큰 움직임 그래프, 최근 낙상 후보·감지 기록과 장치 연결 상태
- `공간 설정 · 데이터셋`: 채널·빈 공간 통합 보정, 공간 프로필과 참조 데이터셋 관리
- `행동 데이터 수집`: 의도적인 학습·검증 데이터 수집과 앱 알림 테스트

평상시에는 `실시간 모니터링` 탭만 확인하면 된다. 움직임 그래프 오른쪽의 낙상
이력은 splitter 경계를 드래그해 폭을 조절할 수 있다.
`낙상 후보·최종 감지 소리`는 기본으로 켜져 있으며 ML 또는 Radar 후보에는 1회,
두 근거가 결합된 최종 낙상 의심에는 3회 울린다. 연속 후보음은 3초 동안 억제하며,
소리가 필요 없으면 체크를 해제한다.

`실험적 Radar 단독 보조 알림`은 현재 S3 환경에서 ML이 실제 침대 낙상을 놓치는
동안 제한적으로 시험할 수 있지만 기본값은 꺼져 있다. 켜면 Radar 신뢰 지표
90% 이상, 충격비 5 이상, 8초 무회복 후보가 ML 없이 15초를 지나면
`radar_high_confidence_fallback` 최종 보조 경보로 승격해 소리와 앱 알림을 보낸다.
ML+Radar 융합보다 오탐 가능성이 높으며 검증된 의료 안전 기준이 아니다.

Jitter 그래프의 x축은 실제 시각이며 최근 10분 신호를 메모리에 보관한다. 행동
판정이 발생하면 해당 시각에 `움직임`, `정지`, `ML 보행`, `ML 기타 움직임`,
`ML 낙상 후보`, `Radar 낙상 후보`, `최종 낙상` 마커가 표시된다. 마커 종류마다
기본 높이를 사용하며 가까운 시각에 반복되면 최대 11개의 촘촘한 높이 안에서
빈 줄로 이동해 라벨이 겹치지 않게 표시한다. 삼각형·마름모 등의 기호는 글씨와
분리하지 않고 같은 라벨 앞에 붙여 표시한다. 기본값인
`실시간 따라가기`를 끄거나 그래프를 가로로 드래그하면 현재 화면이 더 이상
실시간 끝으로 이동하지 않아 과거 신호를 확인할 수 있다. `← 이전 30초`와
`다음 30초 →`로 구간을 이동하고 `현재로`를 누르면 실시간 추적을 다시 시작한다.
Radar가 무회복 8초를 확인한 뒤 후보를 내더라도 마커는 확인 완료 시각이 아니라
처음 충격이 기록된 시각에 놓인다.

| 표시 | 의미 |
|---|---|
| `MOVEMENT DETECTED` | RX 공식 펌웨어가 움직임으로 판정 |
| `STATIC` | RX 공식 펌웨어가 정지로 판정 |
| `재실 상태: 재실 · 움직임 있음` | 사람이 있고 움직이는 상태로 판정 |
| `재실 상태: 재실 · 정지 상태` | 사람이 있으나 현재 움직임은 적은 상태로 판정 |
| `재실 상태: 부재` | 빈 상태가 보수적인 확인 시간 동안 지속됨 |
| `재실 상태: 판단 불가` | 보정·예열·링크 상태 때문에 재실 판정을 신뢰할 수 없음 |
| `WAITING FOR NEXT RADAR RESULT` | 10초 이상 새 Radar 결과가 없음 |
| `SERIAL ERROR` | COM 포트 열기 또는 직렬 통신 오류 |
| `Samples` | 수신한 Radar 결과의 누적 개수 |
| `Jitter` | 단기 CSI 변화량 |
| `Threshold` | RX가 출력한 움직임 기준 참고값 |
| `정지 재실 기준 준비됨` | 현재 보정 이후의 빈방·정지 재실 데이터가 분리되어 보조 판정 활성화 |
| `정지 재실 기준 미구성` | 기준 데이터가 부족하거나 겹쳐 공식 `someone` 폴백 사용 |
| `자동 행동 감지: 움직임/정지` | 평상시 Radar 상태가 안정화되어 행동 전이로 기록됨 |
| `자동 행동 감지: 낙상 의심` | 충격성 변화 뒤 회복 움직임 없음 규칙이 성립함 |

그래프:

- 초록색 `jitter`: 실제 CSI 움직임 반응값
- 보라색 `move threshold`: RX가 출력한 움직임 기준 참고선
- 가로축: 실제 시각 기준으로 최근 10분을 메모리에 보관한다. `실시간 따라가기`를
  끄거나 그래프를 가로로 드래그하면 이전 구간을 확인할 수 있다.

그래프 위의 지표 안내는 판정 단계를 다음과 같이 구분한다.

| 표시 | 단계 | 의미 | 서버 알림 |
|---|---|---|---|
| `정지`, `움직임` | Radar 상태 | RX가 판단한 현재 움직임 상태 | 없음 |
| `ML 보행`, `ML 기타 움직임` | ML 화면 분류 | 최근 ML 출력의 대표 행동 | 없음 |
| 분홍 오각형 `ML 낙상성 분류(중간)` | ML 화면 분류 | 모델이 해당 창을 낙상 성향으로 분류한 중간 결과. 후보 확정이나 최종 낙상이 아님 | 없음 |
| 파랑 다이아몬드 `ML 낙상 후보` | 융합 후보 | ML 낙상 점수가 기준을 넘은 에피소드. 15초 안의 Radar 후보를 기다림 | 없음, 후보음 1회 |
| 주황 사각형 `Radar 낙상 후보` | 융합 후보 | 충격성 변화 뒤 8초 무회복 규칙이 성립. 15초 안의 ML 후보를 기다림 | 없음, 후보음 1회 |
| 빨강 `× 최종 낙상` | 최종 경보 | ML 후보와 Radar 후보가 결합됨 | 경고음 3회 및 서버 알림 |
| 주황 `× Radar 보조 낙상` | 실험적 최종 경보 | 옵션을 켰을 때만 고신뢰 Radar 후보를 ML 없이 승격 | 경고음 및 서버 알림 |

`×`는 실패나 취소를 뜻하지 않고 **최종 경보가 발생한 시각**을 표시한다.

움직임 판정에는 버퍼와 이상치 조건도 사용되므로 한 시점의 두 선만으로 전체 판정을 단정하지 않는다.

### 3.1 재실 상태 읽는 방법

재실 상태는 행동 종류를 분류하지 않는다. RX가 출력하는 `someone`, `moving`,
`wander`를 최근 시간 창에서 안정화해 아래 네 상태로만 표시한다.

| 내부 상태 | 화면 표시 | 의미 |
|---|---|---|
| `PRESENT_ACTIVE` | `재실 · 움직임 있음` | 현재 움직임이 잡힌 재실 상태 |
| `PRESENT_STATIC` | `재실 · 정지 상태` | 정지 재실 기준 또는 공식 `someone` 신호가 유지되는 상태 |
| `ABSENT` | `부재` | 빈방 기준 신호와 움직임 없음이 지속됨 |
| `UNKNOWN` | `판단 불가` | 표본 부족, 보정 필요, 채널 비교, 링크 중단 또는 직렬 오류 |

기본 판정은 최근 5초의 Radar 결과를 사용하며 최소 8개 표본을 기다린다.
재실 신호 비율이 60% 이상이면 재실 후보로 보고 약 1초 확인한다. 현재 표본에서
움직임이 잡히면 거짓 부재를 줄이기 위해 즉시 `PRESENT_ACTIVE`로 올린다. 반대로
재실 신호가 20% 이하이고 움직임이 없는 상태가 15초 동안 이어져야 `ABSENT`로
내린다. 경계 구간에서는 직전 상태를 유지한다.

현재 공간 프로필에 같은 보정 이후 수집한 유효한 `empty_room`과
`standing_static` 또는 `lying_static` 세션이 모두 있으면 PC 모니터가
`wander ÷ someone threshold` 평균으로 공간 전용 정지 재실 기준을 만든다.
빈방 세션 중 가장 높은 평균과 정지 재실 세션 중 가장 낮은 평균이 충분히
분리될 때만 이 기준을 사용한다. 데이터가 없거나 두 범위가 겹치면 기준을
자동으로 비활성화하고 기존 공식 `someone` 결과로 돌아간다. 다른 공간에서
가져온 참조 데이터셋은 이 공간 전용 기준에 사용하지 않는다.

`STATIC`은 움직임 판정일 뿐 부재를 뜻하지 않는다. 사람이 소파나 침대에서 오래
정지한 경우에도 정지 재실 기준 신호가 유지되면 `PRESENT_STATIC`이어야 한다. Radar
데이터가 10초 넘게 끊기거나 공간 프로필에 빈 공간 보정값이 없으면 이전 재실
상태를 계속 보여주지 않고 `UNKNOWN`으로 바뀐다.

이 기능은 현재 고정 배치 실험용 기준선이다. 사람 수와 신원을 구분하지 않으며,
문·가구·선풍기·반려동물과 감지 사각지대의 영향을 받을 수 있다. 실제 알림이나
외출 확정에 사용하기 전에는 빈방, 의자, 소파, 침대와 방 구석 위치를 여러 날
반복 측정해 거짓 부재율을 먼저 확인한다.

### 3.2 평상시 자동 행동 기록과 낙상 의심 알림

빈 공간 보정이 완료된 프로필에서는 별도의 `행동 수집 시작` 버튼을 누르지 않아도
모니터가 평상시 Radar 표본과 `ml/v_main/model.pt`를 함께 사용한다. RX의 원본
`CSI_DATA` 문자열에서 104개 I/Q 값을 읽고, 각 I/Q 쌍을 amplitude로 변환한 최근
950개 × 52개 프레임을 background worker에서 로컬 추론한다. 원본 문자열, phase,
RSSI와 기타 metadata가 모델에 직접 입력되는 것은 아니다. 공식 `moving`이
끝난 뒤에도 3초 동안 tail window를 확인한다. 행동 수집, 채널 비교와 빈 공간
보정 중에는 실험 동작을 실제 알림으로 오인하지 않도록 자동 감지를 잠시 멈춘다.
모델이 정상 로드되면 모니터가 RX에 LLTF decimal 원시 CSI 출력을 자동으로
활성화한다. 펌웨어 명령 인자의 철자만 호환성을 위해 `LLFT`를 사용한다. 별도의
공식 ESP-Radar GUI에서 raw display를 켤 필요가 없다.

모니터를 열기 전에 checkpoint 자체를 바로 확인하는 명령은
[macOS 사용법](usage-macos.md)과 [Windows 사용법](usage-windows.md)에 있다.

`status: ok`, 모델 버전, 실행 장치와 `inputShape: [950, 52]`가 출력되면 로컬
runtime 경로가 정상이다. 함께 출력되는 `syntheticPrediction`은 인공 입력에 대한
구동 점검 결과일 뿐 행동 정확도 수치가 아니다.

자동 기록은 날짜별 JSON Lines 파일에 추가된다.

```text
data/events/YYYY-MM-DD.jsonl
```

각 줄에는 감지 시각, 프로필·공간, 행동 라벨, 판단 출처, 신뢰 지표와 근거가
들어간다. 낙상 의심 알림의 `sending`, `delivered`, `failed`, `skipped` 전달 결과도
같은 파일에 남으므로 앱 서버 장애와 미설정 상태를 나중에 확인할 수 있다.
이 파일은 자동 감지와 알림 상태를 나중에 추적하기 위한 **이벤트 기록**이며,
`data/raw`에 저장되는 원시 `CSI_DATA` 수집 JSONL과는 다른 파일이다. 모니터링만
실행할 때 원시 CSI를 계속 저장하지는 않는다.

GUI의 `최근 낙상 후보·감지 기록 (최신순)` 영역에는 최근 20건을 다시 불러와
표시한다. 앱 서버가 없거나 알림 전송에 실패해도 다음 정보는 GUI와 JSONL에 남는다.

- 로컬 감지 시각
- ML 후보, Radar 후보 또는 최종 융합 낙상 의심 구분
- 신뢰 지표와 판단 출처
- 충격비, 무회복 시간과 최대 ML 낙상 점수
- window/event ID와 앱 알림 전달 상태

겹치는 window에서 나온 ML 낙상 결과는 여러 번의 낙상이 아니라 한 행동 사건으로
묶는다. ML `fall_suspected` score 0.8 이상인 사건과 Radar의
`jitter / move_threshold` 2.5 이상 충격 후 8초간 회복 움직임 없음이 15초 안에서
일치할 때만 최종 낙상 의심 알림을 보낸다. ML과 Radar 중 어느 쪽이 먼저
확정되어도 후보를 보관해 양방향으로 결합한다. 한쪽 근거만 있으면 후보로 기록하고
알림은 보내지 않는다. 단, 사용자가 `실험적 Radar 단독 보조 알림`을 켠 경우에는
위의 고신뢰 Radar 조건으로 제한된 보조 경보를 허용한다. 같은 최종 사건은 60초
동안 다시 알리지 않는다.

실시간 탭의 `융합 진단`에는 현재 상태를 다음처럼 표시한다.

- `Radar 충격 관측 · 무회복 확인 중`: 이전 충격 이후 8초 판정의 남은 시간
- `ML 낙상 후보 감지`: 15초 안의 Radar 충격 후보를 기다리는 중
- `Radar 낙상 후보 감지`: 15초 안의 ML 후보를 기다리는 중
- `융합 미완료`: 반대 근거가 시간 안에 없어 알림하지 않음
- `ML+Radar 결합 완료`: 최종 낙상 의심으로 앱 알림 전송 판단
- `고신뢰 Radar 단독 보조 경보`: 실험 옵션에 따라 ML 미확인 상태로 알림 전송 판단
- `전달 완료/실패/미전송`: 입력한 앱 서버 주소에 대한 최종 처리 결과

0.8은 공개 ESP32-C3 모델을 ESP32-S3 실시간 파이프라인에 연결하기 위한 초기
통합 기준이며 보정된 안전 확률이 아니다. 실제 생활 환경에서 앉기, 눕기, 물건
줍기와 큰 팔 동작을 포함해 시간당 오탐률과 낙상 recall을 측정한 뒤 validation
데이터로 조정해야 한다.
Radar 후보는 충격 직후가 아니라 8초 무회복 확인 뒤 나타나고, ML은 최근 950프레임
창을 사용하며 결과를 화면에 5초 유지한다. 따라서 사람이 이미 멈춘 뒤 결과가
표시될 수 있다. 이는 표시 시점과 원인이 된 신호 시점이 다른 것이며, 그래프의
행동 마커는 원인이 된 시각에 기록된다.

앱 서버 주소는 GUI의 `낙상 알림 서버`에 입력하거나 실행 전에 운영체제의
`CARNATION_EVENT_API_URL` 환경 변수로 준다. 환경 변수가 없으면 GUI 기본값은
`http://localhost:8080`이다.

주소가 비어 있어도 감지 기록은 남고 알림 전달만 `skipped`로 기록된다.

## 4. 채널 + 공간 통합 보정

처음 설치하거나 배치가 바뀌었거나 정지 중에도 `MOVEMENT DETECTED`가 계속되면
채널 비교와 빈 공간 보정을 한 번에 다시 실행한다.

1. TX와 RX를 사용할 최종 위치에 고정한다.
2. `채널 + 공간 통합 보정 (약 100초)` 버튼을 누른다.
3. 확인창에서 `Yes`를 선택한다.
4. 10초 카운트다운 안에 감지 공간에서 완전히 나간다.
5. GUI가 채널 1·6·11을 차례로 안정화하고 각 15초 동안 링크를 측정한다.
6. 최적 채널을 적용한 뒤 같은 채널에서 30초 빈 공간 보정이 자동으로 이어진다.
7. `통합 보정 완료 - 프로필 저장됨`이 표시되면 돌아온다.
8. 완료 창에서 채널별 결과와 최종 선택 채널을 확인한다.
9. 먼저 30초간 정지해 `STATIC`인지 확인한다.
10. 이후 걸어서 `MOVEMENT DETECTED`로 바뀌는지 확인한다.

통합 보정이 끝날 때까지 방에 다시 들어오거나 보드, 문과 가구를 움직이지 않는다.
보정 중 모니터를 닫지 않는다. 부득이하게 닫으면 모니터가 진행 중인 Radar 학습을
중지하지만, 다시 실행한 뒤 통합 보정을 처음부터 수행하는 편이 안전하다.

### 다시 보정해야 하는 경우

- RX 전원 재연결 또는 펌웨어 재시작
- TX/RX 위치, 높이 또는 안테나 방향 변경
- 다른 집이나 방으로 이동
- 큰 가구 이동 또는 문 상태의 큰 변화
- 정지 중 움직임 오탐 반복

보정이 정상 완료되면 현재 공간 프로필에 공식 Radar 임계값이 자동 저장된다.

## 4.1 공간 프로필 저장과 복원

프로필이 하나도 없으면 빈 `기본 공간` 프로필이 생성된다. 배치·거리·보정값·MAC이
모두 비어 있는 것이 정상이며, 아래 절차로 자신의 환경 값을 채운다.

### 프로필 선택

1. `공간 프로필` 영역의 드롭다운을 연다.
2. 사용할 공간을 선택한다.
3. 아래의 저장 채널, 보정값 유무와 연결 데이터 개수를 확인한다.
4. 저장 설정을 보드에 불러오려면 `공간 프로필 적용`을 누른다.

드롭다운에서 선택만 하면 보드 설정은 바뀌지 않는다. 채널과 보정값은
`공간 프로필 적용`을 눌렀을 때 전송된다. 반면 선택한 상태에서 채널 비교,
빈 공간 보정 또는 행동 수집을 실행하면 결과는 현재 선택 프로필에 저장된다.

### 새 프로필 추가

1. `새 프로필 추가`를 누른다.
2. 알아보기 쉬운 공간 이름을 입력한다.
3. TX와 RX의 실제 배치를 설명한다.
4. 두 보드의 직선거리(m)를 입력한다.
5. 새 프로필이 드롭다운에서 자동 선택되었는지 확인한다.
6. 보드를 최종 위치에 놓고 빈 공간 보정을 실행한다.

새 프로필은 현재 보드 채널을 초기 채널로 저장하지만 보정값은 비어 있다.
첫 빈 공간 보정이 끝나면 해당 프로필에 새 보정값이 저장된다.

### 프로필 정보 수정

1. 드롭다운에서 수정할 프로필을 선택한다.
2. `선택 프로필 수정`을 누른다.
3. 공간 이름, 배치 설명, TX-RX 직선거리, TX 위치·높이와 RX 위치·높이를
   현재 설치 상태에 맞게 입력한다.
4. 수정 완료 메시지를 확인한다.

공간 이름만 바꾸면 기존 보정값은 유지된다. 거리, 배치 설명, TX 위치 또는
RX 위치가 달라지면 CSI 기준선도 달라질 수 있으므로 기존 보정값은 자동으로
삭제되고 `보정값 없음`으로 바뀐다. 이때는 최종 위치에서 빈 공간 보정을 다시
실행해야 재실 판단이 시작된다.

### 프로필 삭제

1. 드롭다운에서 삭제할 프로필을 선택한다.
2. `선택 프로필 삭제`를 누른다.
3. 프로필 이름과 연결 데이터 개수를 확인한다.
4. 삭제 확인창에서 `Yes`를 누른다.

삭제해도 `data/raw`, `data/manifests`, `data/processed`의 기존 데이터는
유지된다. 프로필 JSON은 `data/profiles/archive`로 이동하므로 필요하면
복구할 수 있다. 마지막 남은 프로필은 삭제할 수 없다. 프로필을 삭제해도
현재 보드에 이미 적용된 채널과 보정값은 즉시 바뀌지 않는다.

처음 저장할 때:

1. TX와 RX를 감지할 구역을 사이에 둔 대각선 위치에 놓는다.
2. GUI 상단 공간 프로필에 `보정값 없음`이 표시되면 빈 공간 보정을 실행한다.
3. `CALIBRATION COMPLETE - PROFILE SAVED`가 표시되는지 확인한다.
4. 프로필 표시가 `보정값 저장됨`으로 바뀌면 저장이 끝난 것이다.

다른 곳에서 사용한 뒤 돌아왔을 때:

1. TX와 RX를 프로필에 기록된 위치, 거리, 높이와 안테나 방향으로 복원한다.
2. `공간 프로필 적용`을 누르고 배치 확인창에서 `Yes`를 누른다.
3. GUI가 채널과 저장된 공식 Radar 설정을 적용할 때까지 약 2초 기다린다.
4. 30초간 움직이지 않아 `STATIC`인지 확인한다.
5. 움직여 `MOVEMENT DETECTED`로 바뀌는지 확인한다.

큰 가구, 문 상태 또는 보드 배치가 달라졌거나 정지 오탐이 반복되면 저장된
값을 계속 쓰지 말고 빈 공간 보정을 다시 실행한다. 새 보정이 끝나면 같은
프로필의 값이 갱신된다.

## 5. 링크 품질

모니터의 등급은 프로젝트 편의 기준이며 Espressif 공식 보증 기준은 아니다.

| 표시 | RSSI | 의미 |
|---|---:|---|
| `GOOD` | `-65 dBm` 이상 | 초기 실험에 충분한 여유 |
| `FAIR` | `-75~-66 dBm` | 동작 가능하지만 배치 영향에 민감할 수 있음 |
| `WEAK` | `-76 dBm` 이하 | 거리·방향·장애물 조정 권장 |
| `ACTIVE` | RSSI 로그 없이 Radar 데이터 수신 | 링크와 Radar 처리 동작 중 |

RSSI는 0에 가까울수록 강하다. `-55 dBm`이 `-75 dBm`보다 강하다.

첫 실험에서는 `Packets`가 대략 30 Hz 이상 유지되는지 확인한다. `Wi-Fi CSI link data paused`와 함께 `Samples`도 10초 이상 멈추는 상황이 반복되면 TX 전원과 배치를 점검한다.

## 6. 권장 배치

- TX-RX 거리: 약 2~5 m
- 높이: 바닥에서 약 0.8~1.2 m
- 두 보드 안테나 방향을 비슷하게 정렬
- 주 이동 동선이 TX-RX 경로를 가로지르게 설치
- 금속 표면, PC 본체, 냉장고와 벽에 밀착하지 않기
- 보정 후 보드를 움직이지 않기

Wi-Fi CSI는 원형 감지 범위를 만드는 센서가 아니다. TX-RX 직접 경로와 주변 다중경로의 변화를 감지하므로 같은 거리라도 방향, 장애물과 이동 위치에 따라 결과가 달라진다.

## 7. 데이터 수집

수집 전에 프로젝트 모니터와 공식 GUI를 닫는다.

### GUI 안내형 행동 수집

프로젝트 모니터 한 개만 실행하고 `행동 데이터 수집` 탭을 연 뒤 다음 순서로 수집한다.

1. 공간 프로필과 현재 채널이 맞는지 확인한다.
2. 기본값인 `수집 후 실제 행동 선택`을 그대로 두거나, 예정 행동을 선택한다.
3. 준비 시간과 수집 시간을 정한다.
4. `lie_down_slow`, `get_up_from_bed`처럼 시작 시점이 중요한 행동은 중간 행동 신호를 켠다.
5. `행동 수집 시작`을 누르고 준비 카운트다운 동안 자세를 잡는다.
6. 시작음 뒤 수집을 진행하고, 중간 신호가 울리면 지정 행동을 시작한다.
7. 종료음이 울리면 방금 실제로 수행한 행동을 선택한다.
8. 마지막으로 이번 회차가 유효했는지 선택한다.

저장 결과:

```text
data/raw/<세션-id>.jsonl
data/manifests/<세션-id>.json
data/processed/<세션-id>.md
```

수집 중 원본 JSONL의 라벨은 `unlabeled`로 기록한다. 수집이 끝난 뒤 선택한
실제 행동이 manifest의 최종 `label`이 되며, 특징 생성·예측·데이터셋
내보내기는 이 manifest 라벨을 정답으로 사용한다. 종료 라벨 선택창을
취소하면 원본은 보존하지만 `unlabeled`·무효 세션으로 처리하여 학습과
내보내기에서 제외한다. 예정 행동과 실제 행동이 다르면 실제 행동으로
저장하고 `labelCorrected`에 수정 여부를 남긴다.

manifest에는 `profileId`와 `roomId`가 함께 기록되고, 세션 ID는 사용 중인
`data/profiles/<profileId>.json`에도 연결된다. 따라서 행동 데이터는 라벨뿐
아니라 수집한 공간·배치·채널·보정 상태를 기준으로 묶어서 비교한다.

`공간 설정 · 데이터셋` 탭의 `프로필 고정 Wi-Fi 채널`에서 채널 1·6·11 중
하나를 프로필별로 선택할 수 있다. `채널 저장·적용`은 선택값을 프로필에
저장하고 TX/RX에 전환 명령을 보낸다. 채널을 변경하면 이전 채널의 빈방
보정값은 자동으로 무효화되지만 기존 수집 파일은 삭제하지 않는다.

고정 채널에서 새 데이터를 수집하려면 `선택 채널 빈방 보정 (약 40초)`을
사용한다. 이 버튼은 선택 채널을 저장·적용한 뒤 10초 퇴장 시간과 30초 빈방
보정을 실행한다. 자동으로 최적 채널을 고르는 `채널 + 공간 통합 보정`과 달리
선택한 채널을 바꾸지 않는다. 보정 완료 후 GUI의 현재 채널과 프로필의 저장
채널이 일치하는지 확인한 다음 행동 데이터를 수집한다.

`data/` 아래의 수집 결과와 프로필은 저장소에 올라가지 않는다. 개인 환경
정보가 들어 있기 때문이며, 각자 자신의 PC에서 생성된다.

추가 행동 라벨:

| 행동 | 라벨 | 권장 수집 |
|---|---|---|
| 빠르게 앉기 | `sit_down_fast` | 20초, 10초 신호 |
| 물건 줍기 | `pick_up_object` | 20초, 10초 신호 |
| 매트리스 위 모의 낙상 | `fall_simulated_mattress` | 20초, 10초 신호 |

모의 낙상은 수집 전에 `모의 낙상 안전 수집`을 체크해야 한다. 예정 행동으로
`fall_simulated_mattress`를 선택하면 이 항목이 자동으로 체크된다. 이어서
나오는 안전 확인창에서 실제 바닥 낙상은 수행하지 않으며, 매트리스와
보조자가 준비되지 않았으면 `Cancel`을 누른다. 안전 확인 여부는 manifest의
`safetyProtocolConfirmed`에 기록된다. 사전 안전 확인 없이 종료 라벨을
모의 낙상으로 선택하면 원본은 보존하지만 해당 세션은 자동으로 무효 처리한다.

### 행동 인식용 특징 CSV 생성

반복 수집 현황을 확인하거나 모델 학습 입력을 만들 때 실행한다.

```bash
python -m csi_gateway features --profile-id <profileId> --project-root .
```

`<profileId>`는 `data/profiles`의 파일 이름이다. 결과는
`data/processed/<profileId>-features.csv`에 저장된다. 무효로 표시한 세션과
링크 시험처럼 행동 라벨이 아닌 세션은 자동으로 제외된다.

행동당 세션이 한두 개뿐인 상태에서는 행동 분류 모델을 학습·평가하지 않는다.

### 행동 유사도 시험

같은 프로필에 기준 세션이 쌓인 행동은 새 수집이 끝날 때 실험용 예측을 표시한다.
기준 세션이 없는 라벨은 완료창에 기준 데이터가 없다고 표시된다.

1. 기준 세션을 수집한 것과 같은 프로필을 선택하고 적용한다.
2. 필요하면 예정 행동을 선택하거나 기본값인 종료 후 선택을 유지한다.
3. 기존 예비 데이터와 맞추기 위해 수집 시간을 30초로 설정한다.
4. 정지·걷기는 30초 동안 해당 상태를 유지한다.
5. 눕기·일어나기는 중간 행동 신호를 켜고 15초에 실행한다.
6. 수집 종료 후 실제 수행한 행동을 정답 라벨로 선택하고 유효 데이터로 저장한다.
7. 완료창의 `참고 예측`이 선택한 실제 라벨과 같은지 확인한다.

수집 시작은 한 번, 중간 행동 신호는 두 번, 정상 수집 종료는 세 번의 짧은
알림음으로 구분한다. GUI를 닫아 수집이 강제로 중단된 경우에는 정상 종료음을
울리지 않는다.

예측은 현재 세션을 기준 데이터에서 제외하고 기존 행동 세션들의 특징과
거리만 비교한다. `분리도`는 가장 가까운 행동과 두 번째 행동 사이의 상대적
거리이며 확률이나 검증된 신뢰도가 아니다. 행동당 기준 세션이 한 개뿐이므로
결과가 맞거나 틀리는지 확인하는 기능 시험으로만 사용한다.

`sit_down_fast`, `pick_up_object`, `fall_simulated_mattress`는 아직 기존 기준
세션이 없으므로 완료창에 기준 데이터가 없다고 표시된다.

### 안전한 앱 알림·융합 시험

실제 몸으로 넘어지는 동작을 반복하지 않는다. 앱 서버 주소를 입력한 뒤 두 버튼을
목적에 맞게 사용한다.

- `앱 알림 테스트`: 감지·융합·경고음을 건너뛰고 최종 알림 HTTP 전송 계약만 확인
- `알림 경로 시뮬레이션 (센서 제외)`: 합성 Radar 후보를 먼저 만들고 ML 후보를 나중에 확정해
  양방향 융합, 감지 경고음, 이벤트 JSONL 기록과 HTTP 전송을 함께 확인

알림 경로 시뮬레이션은 `safe-simulation-...` ID와 `안전 시뮬레이션` 근거를 기록한다.
센서나 모델이 실제 낙상을 정확하게 인식한다는 의미는 아니다.
버튼을 누르면 확인 대화상자 없이 즉시 로컬 융합·경고음·JSONL 시험을 수행한다.
서버 주소가 있으면 앱 테스트 알림까지 보내며, 주소가 비어 있으면 로컬 시험만
완료하고 알림 전달은 `skipped`로 기록한다.

1. 보호자 앱 서버를 실행하고 같은 Wi-Fi에서 `GET /health`가 응답하는지 확인한다.
2. 같은 Mac/PC에서 서버를 실행하면 기본값 `http://localhost:8080`을 사용한다.
   다른 장치의 서버라면 GUI에 `http://<서버-IP>:8080`을 입력한다.
3. HTTP 경로만 확인할 때는 `앱 알림 테스트`를 누른다.
4. 전체 이벤트 경로를 확인할 때는 `알림 경로 시뮬레이션 (센서 제외)`을 누른다.
5. GUI에 `앱 알림 전달 완료`가 표시되고 보호자 폰에 테스트 알림이 오는지 확인한다.

ESP32나 행동 수집 없이 즉시 확인하려면 서버 주소를 입력하고
`앱 알림 테스트` 버튼을 누른다. 버튼을 누를 때마다 고유한 `window_id`의 테스트
이벤트가 생성되므로 서버의 중복 방지에 걸리지 않고 새 알림으로 전송된다.

주소는 GUI 대신 환경 변수 `CARNATION_EVENT_API_URL`로 미리 지정할 수도 있다.
기본 서버 주소와 전체 주소(`.../api/v1/events`)를 모두 지원한다. 같은 세션을
다시 전송하면 같은 `window_id`가 사용되어 서버에서 중복 알림을 막을 수 있다.

ESP32와 실제 수집 없이 서버·FCM 경로만 먼저 확인하려면 테스트 이벤트 한 건을
보낸다.

```bash
python -m csi_gateway fall-alert-test \
  --server http://<서버-IP>:8080 \
  --room-id living-room
```

서버가 `201`로 접수하면 생성한 `window_id`를 출력한다. 이 명령은 실행할 때마다
새 ID를 사용하므로 매번 새 테스트 알림으로 처리된다.

전송 이벤트의 점수 1.0은 사용자가 수집 라벨과 유효성을 확인했다는 테스트 값이며
분류 확률이 아니다. 상시 감지기를 추가할 때는 검증된 모델 점수와 재실·회복 근거로
바꾸고 `send_fall_event()` 호출부만 연결한다.

### 팀 데이터셋 내보내기·가져오기

현재 프로필의 유효한 행동 세션을 공유하려면 `참조 데이터셋` 영역의
`현재 프로필 데이터 내보내기`를 누르고 `.csi-dataset.zip`으로 저장한다.
번들에는 원본 JSONL, 세션 manifest, 출처·라벨과 체크섬이 포함되지만 공간
프로필에 저장된 보드 MAC과 상세 배치 위치는 포함되지 않는다. 원본 직렬 로그에
부팅 시점의 장치 식별 로그가 들어 있을 가능성은 있으므로 팀 외부로 전달하기
전에는 내용을 별도로 확인한다.

동료 데이터는 `데이터셋 번들 가져오기`로 검사한 뒤 목록에서 선택하고
`선택 데이터 연결`을 누른다. 연결된 데이터는 현재 공간의 행동 유사도 참고
세션에 포함된다. 공식 채널과 빈방 보정값은 바뀌지 않는다. 연결을 취소하려면
같은 항목에서 `선택 데이터 연결 해제`를 누른다.

현재는 우리 프로젝트에서 내보낸 ESP-Radar JSONL 번들만 지원한다. 다른
오픈소스 포맷은 자동 변환하지 않는다. 자세한 규칙과 명령줄 사용법은
[팀 데이터셋 공유](dataset-sharing.md)를 참고한다.

### 링크 설정 비교 규칙

채널이나 채널 폭을 비교할 때는 다음 조건을 고정한다.

- TX-RX 거리: 60cm의 표시된 안정 배치
- 회차당 측정 시간: 120초
- 설정별 반복: 3회
- 측정 중 보드 위치와 방향을 변경하지 않음
- 원본 JSONL과 세션 manifest를 모두 보관

설정별로 Radar sample 수, 활성 구간의 packet Hz, RSSI, 10초 이상 공백 횟수, 최장 공백, paused 시간과 active 비율을 비교한다. packet Hz는 링크 결과가 생성된 순간의 수치이므로 전체 시간의 연속성과 함께 해석해야 한다.

### GUI 채널 + 공간 통합 보정

TX는 보조배터리에 연결하고 RX만 PC의 UART 포트에 연결한 상태로 실행할 수
있다. 원하는 최종 위치에서 처음부터 링크를 잡을 수 있다면 그 위치에서 바로
아래 절차를 수행한다.

1. 두 보드의 전원을 켜고 GUI에서 Radar 샘플이 들어오는지 확인한다.
2. `채널 + 공간 통합 보정 (약 100초)`을 누른다.
3. 10초 안에 방을 나가고 완료 안내까지 빈 상태를 유지한다.
4. GUI가 채널마다 안정화 4초, 측정 15초를 진행한다.
5. 선택 채널에서 30초 빈 공간 보정이 자동으로 이어지는지 확인한다.
6. 완료 창에서 평균/최저 패킷 Hz, RSSI, 최대 Radar 공백과 선택 채널을 확인한다.
7. 선택된 채널이 GUI의 `Current Wi-Fi channel`에 표시되는지 확인한다.
8. 보정 후 정지와 움직임을 다시 확인한다.

채널 비교 중 TX를 PC에 연결할 필요는 없다. 선택 채널은 PC의 공간 프로필에
저장되지만 보드 NVS에는 저장되지 않으므로 두 보드 재시작 직후에는 기본
채널 6으로 돌아간다. 이후 `공간 프로필 적용`을 누르면 저장 채널로 다시
전환할 수 있다. 전환 중 링크가 완전히 끊어지면 두 보드의 RST를 모두 눌러
채널 6으로 복구한다. 상세 설계와 제한은 [채널 보정](channel-calibration.md)을 참고한다.

### 최종 위치에서 처음 링크가 잡히지 않을 때

1. TX는 **처음부터 보조배터리로 켜고**, RX는 PC에 연결한다.
2. 두 보드를 약 30~60cm로 가까이 두고 안테나 방향을 맞춘다.
3. `Samples`와 `Packets`가 연속 증가하는지 확인한다.
4. `채널 + 공간 통합 보정 (약 100초)`을 실행해 초기 채널과 기준값을 저장한다.
5. 두 보드를 재시작하거나 TX 전원을 끄지 않은 채 TX를 최종 위치 쪽으로
   30~50cm씩 옮긴다.
6. 단계마다 5~10초 기다리며 `Packets`, RSSI와 paused 표시를 확인한다.
7. 최종 위치에서 30~60초 동안 링크가 유지되면 공간 프로필의 거리와 위치를
   수정한다.
8. 방을 비우고 최종 위치에서 통합 보정을 다시 실행한다.
9. 정지·움직임·재실 상태가 예상대로 바뀌는지 확인한다.

TX를 PC에서 뽑아 보조배터리로 옮기면 전원이 재시작되며 선택 채널이 6으로
돌아간다. 따라서 이 절차에서는 채널 비교를 시작하기 전에 TX를 보조배터리에
연결해야 한다. 가까운 거리에서 고른 채널은 연결을 시작하기 위한 초기값이다.
최종 위치에서도 링크가 충분히 안정적이면 그 위치에서 통합 보정을 한 번 더
실행하는 것이 더 정확하다.

현재 1·6·11은 HT20에서 서로 겹치지 않는 저·중·고 대표 채널이다. 현재 자동
비교는 1~11 전체에서 절대 최적값을 찾는 기능은 아니다.

운영체제별 수집 명령은 [macOS 사용법](usage-macos.md)과
[Windows 사용법](usage-windows.md)을 참고한다.

라벨 예시:

```text
empty_room
person_static
walking_slow
walking_fast
sit_stand
```

저장 위치:

```text
data/raw/<session-id>.jsonl
data/manifests/<session-id>.json
```

### 기본 검증 순서

한 배치에서 다음 상태를 각각 1분씩 최소 3회 수집한다.

1. 빈 공간
2. 사람이 앉아서 정지
3. 천천히 걷기
4. 빠르게 걷기
5. 앉기와 일어나기

움직임 감지율, 정지 오탐, 감지 지연, Radar 공백, RSSI, 패킷 빈도와 jitter 분포를 비교한다.

고정 배치 검증 후 거리, 방향, 이동 위치와 장애물을 바꿔 별도 세션을 만든다. 서로 다른 배치를 무작위로 섞지 말고 특정 배치 전체를 테스트용으로 분리한다.

낙상 모의 실험은 움직임/정지 판정이 안정된 뒤 안전 매트와 보조 인력이 준비된 상태에서만 진행한다. 고령자를 모의 낙상에 참여시키지 않는다.

## 8. 펌웨어 빌드와 업로드

평상시 모니터와 수집에는 ESP-IDF가 필요하지 않다. 저장소의 prebuilt HT20
펌웨어는 운영체제별 `flash-prebuilt` 스크립트로 올린다. 소스를 수정하고 직접
빌드할 때만 ESP-IDF v5.0.2와 `third_party/esp-csi`가 필요하다. 명령은
[macOS 초기 세팅](setup-macos.md) 또는 [Windows 초기 세팅](setup-windows.md)을
참고한다.

## 9. 공식 Espressif GUI

공식 GUI에는 Raw CSI, Radar, 보정, 통계와 행동 수집 기능이 있다. 현재 Python
환경과의 호환 문제로 갱신이 멈출 수 있어 기본 확인에는 프로젝트 모니터를
사용한다. Windows 실행 명령은 [Windows 사용법](usage-windows.md)을 참고한다.

공식 GUI와 프로젝트 모니터를 동시에 실행하지 않는다.

## 10. 문제 해결

### 직렬 포트 이름이 바뀜

정상이다. 운영체제별 `ports` 명령으로 다시 확인하고 명령의 포트만 바꾼다.

### 직렬 포트를 열 수 없음

공식 GUI, 프로젝트 모니터, 수집기 또는 `idf.py monitor` 중 하나가 이미 포트를 사용 중인지 확인한다.

### TX RGB LED가 켜지지 않음

송신 펌웨어는 RGB LED로 상태를 표시하지 않는다. 작은 빨간 전원 LED와 RX 수신값으로 판단한다.

### 정지 중에도 계속 움직임으로 표시됨

최종 배치에서 빈 공간 보정을 수행한다. 보정 후에도 반복되면 jitter, 링크 품질과 배치 조건을 기록하고 임계값 조정 전에 데이터를 먼저 수집한다.

### 움직여도 반응이 약함

TX-RX를 2~3 m로 줄이고 높이와 안테나 방향을 맞춘다. 사람의 동선이 두 보드 사이를 가로지르게 한다.

### 잠깐 결과가 멈춤

`WAITING FOR NEXT RADAR RESULT` 후 `Samples`가 다시 증가하면 일시적인 Radar 결과 공백이다. 링크 데이터와 Samples가 모두 장시간 멈추면 TX 전원과 배치를 확인한다.

## 11. 현재 구현 범위

현재 모니터는 Espressif RX 펌웨어의 보정된 `move/static`과 PC의 실험용 공간 전용 재실 판정을 확인하는 도구다. 다음 기능은 아직 구현되지 않았다.

- 여러 사람·여러 배치에서 검증된 서비스 수준의 사람 있음/없음 판정
- 여러 사람·여러 날 데이터로 검증된 행동 종류 분류
- 검증된 실시간 낙상 감지
- 장시간 무활동 규칙
- 보관 프로필 복구 화면
- 선택 채널 NVS 영구 저장과 전환 실패 자동 복구
- 서버 및 Android 알림 연동
