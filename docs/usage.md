# ESP32-S3 Wi-Fi CSI 사용법

최종 확인일: 2026-08-04

이 문서는 현재 하드웨어를 연결하고 움직임을 확인하며 데이터를 수집하는 실제 절차를 설명한다. 설치 버전과 경로는 [개발 환경](environment.md)을 참고한다.

## 문서 동기화 규칙

- 실행 명령, UI, 버튼, 메시지, 보정·수집 절차가 바뀌면 이 문서를 같은 변경에서 수정한다.
- 버전, 설치 경로, 하드웨어 역할 또는 아키텍처가 바뀌면 [개발 환경](environment.md)을 수정한다.
- 한 변경이 환경과 사용 흐름 모두에 영향을 주면 두 문서를 함께 수정한다.
- 코드·설정 변경은 사용자 승인 후 진행하며, 승인된 변경의 문서 동기화는 해당 작업에 포함한다.

## 1. 보드 연결

### TX 송신기

- 보조배터리 또는 USB 전원에 연결한다.
- 두 USB-C 단자 중 어느 쪽을 사용해도 전원 공급은 가능하다.
- 작은 빨간 LED는 전원 표시다. RGB LED가 켜지지 않아도 정상이다.
- 필요하면 전원 연결 후 `RST` 또는 `EN`을 한 번 누른다.
- 보조배터리의 자동 절전으로 빨간 LED가 꺼지지 않는지 확인한다.

### RX 수신기

- 보드의 `UART` USB-C 단자를 PC에 연결한다.
- Windows에서 `USB-Enhanced-SERIAL CH343`으로 표시되는 포트를 사용한다.
- TX와 RX는 USB 선으로 서로 연결하지 않는다.

## 2. 매일 시작하는 순서

PowerShell에서:

프로젝트 폴더로 이동한 뒤:

```powershell
Set-ExecutionPolicy -Scope Process Bypass
```

### 2.1 RX 포트 확인

```powershell
.\.venv\Scripts\python.exe -m csi_gateway ports
```

현재 RX 예시는 `COM8`이다. COM 번호가 바뀌면 이후 명령의 포트를 실제 번호로 바꾼다.

### 2.2 실시간 모니터 실행

```powershell
.\scripts\start-radar-monitor.ps1 -Port COM8
```

공식 GUI, 프로젝트 모니터, 데이터 수집기와 `idf.py monitor`는 같은 COM 포트를 동시에 사용할 수 없다.

## 3. 모니터 읽는 방법

| 표시 | 의미 |
|---|---|
| `MOVEMENT DETECTED` | RX 공식 펌웨어가 움직임으로 판정 |
| `STATIC` | RX 공식 펌웨어가 정지로 판정 |
| `WAITING FOR NEXT RADAR RESULT` | 10초 이상 새 Radar 결과가 없음 |
| `SERIAL ERROR` | COM 포트 열기 또는 직렬 통신 오류 |
| `Samples` | 수신한 Radar 결과의 누적 개수 |
| `Jitter` | 단기 CSI 변화량 |
| `Threshold` | RX가 출력한 움직임 기준 참고값 |

그래프:

- 초록색 `jitter`: 실제 CSI 움직임 반응값
- 보라색 `move threshold`: RX가 출력한 움직임 기준 참고선
- 가로축: 최근 최대 100개 Radar 결과를 `0~100` 범위에 고정해서 표시한다. 마우스로 세로축은 확인할 수 있지만 가로축 확대·축소와 이동은 비활성화되어 있다.

움직임 판정에는 버퍼와 이상치 조건도 사용되므로 한 시점의 두 선만으로 전체 판정을 단정하지 않는다.

## 4. 빈 공간 보정

정지 중에도 `MOVEMENT DETECTED`가 계속되거나 배치가 바뀌었으면 공간 보정을 한다.

1. TX와 RX를 사용할 최종 위치에 고정한다.
2. `Calibrate Empty Room (40 seconds)` 버튼을 누른다.
3. 확인창에서 `Yes`를 선택한다.
4. 10초 카운트다운 안에 감지 공간에서 완전히 나간다.
5. 이어지는 30초 동안 공간을 비우고 보드, 문과 가구를 움직이지 않는다.
6. `CALIBRATION COMPLETE`가 표시되면 돌아온다.
7. 먼저 30초간 정지해 `STATIC`인지 확인한다.
8. 이후 걸어서 `MOVEMENT DETECTED`로 바뀌는지 확인한다.

보정 중 모니터를 닫지 않는다. 부득이하게 닫으면 모니터가 `radar --train_stop`을 전송하도록 구현되어 있지만, 다시 실행한 뒤 보정을 처음부터 수행하는 편이 안전하다.

### 다시 보정해야 하는 경우

- RX 전원 재연결 또는 펌웨어 재시작
- TX/RX 위치, 높이 또는 안테나 방향 변경
- 다른 집이나 방으로 이동
- 큰 가구 이동 또는 문 상태의 큰 변화
- 정지 중 움직임 오탐 반복

보정이 정상 완료되면 현재 공간 프로필에 공식 Radar 임계값이 자동 저장된다.

## 4.1 공간 프로필 저장과 복원

프로필이 하나도 없으면 빈 `기본 공간` 프로필이 생성된다. 배치·거리·보정값·MAC이
모두 비어 있는 것이 정상이며, 아래 절차로 자신의 환경 값을 채운다.

### 프로필 선택

1. `공간 프로필` 영역의 드롭다운을 연다.
2. 사용할 공간을 선택한다.
3. 아래의 저장 채널, 보정값 유무와 연결 데이터 개수를 확인한다.
4. 저장 설정을 보드에 불러오려면 `공간 프로필 적용`을 누른다.

드롭다운에서 선택만 하면 보드 설정은 바뀌지 않는다. 채널과 보정값은
`공간 프로필 적용`을 눌렀을 때 전송된다. 반면 선택한 상태에서 채널 비교,
빈 공간 보정 또는 행동 수집을 실행하면 결과는 현재 선택 프로필에 저장된다.

### 새 프로필 추가

1. `새 프로필 추가`를 누른다.
2. 알아보기 쉬운 공간 이름을 입력한다.
3. TX와 RX의 실제 배치를 설명한다.
4. 두 보드의 직선거리(m)를 입력한다.
5. 새 프로필이 드롭다운에서 자동 선택되었는지 확인한다.
6. 보드를 최종 위치에 놓고 빈 공간 보정을 실행한다.

새 프로필은 현재 보드 채널을 초기 채널로 저장하지만 보정값은 비어 있다.
첫 빈 공간 보정이 끝나면 해당 프로필에 새 보정값이 저장된다.

### 프로필 삭제

1. 드롭다운에서 삭제할 프로필을 선택한다.
2. `선택 프로필 삭제`를 누른다.
3. 프로필 이름과 연결 데이터 개수를 확인한다.
4. 삭제 확인창에서 `Yes`를 누른다.

삭제해도 `data/raw`, `data/manifests`, `data/processed`의 기존 데이터는
유지된다. 프로필 JSON은 `data/profiles/archive`로 이동하므로 필요하면
복구할 수 있다. 마지막 남은 프로필은 삭제할 수 없다. 프로필을 삭제해도
현재 보드에 이미 적용된 채널과 보정값은 즉시 바뀌지 않는다.

처음 저장할 때:

1. TX와 RX를 감지할 구역을 사이에 둔 대각선 위치에 놓는다.
2. GUI 상단 공간 프로필에 `보정값 없음`이 표시되면 빈 공간 보정을 실행한다.
3. `CALIBRATION COMPLETE - PROFILE SAVED`가 표시되는지 확인한다.
4. 프로필 표시가 `보정값 저장됨`으로 바뀌면 저장이 끝난 것이다.

다른 곳에서 사용한 뒤 돌아왔을 때:

1. TX와 RX를 프로필에 기록된 위치, 거리, 높이와 안테나 방향으로 복원한다.
2. `공간 프로필 적용`을 누르고 배치 확인창에서 `Yes`를 누른다.
3. GUI가 채널과 저장된 공식 Radar 설정을 적용할 때까지 약 2초 기다린다.
4. 30초간 움직이지 않아 `STATIC`인지 확인한다.
5. 움직여 `MOVEMENT DETECTED`로 바뀌는지 확인한다.

큰 가구, 문 상태 또는 보드 배치가 달라졌거나 정지 오탐이 반복되면 저장된
값을 계속 쓰지 말고 빈 공간 보정을 다시 실행한다. 새 보정이 끝나면 같은
프로필의 값이 갱신된다.

## 5. 링크 품질

모니터의 등급은 프로젝트 편의 기준이며 Espressif 공식 보증 기준은 아니다.

| 표시 | RSSI | 의미 |
|---|---:|---|
| `GOOD` | `-65 dBm` 이상 | 초기 실험에 충분한 여유 |
| `FAIR` | `-75~-66 dBm` | 동작 가능하지만 배치 영향에 민감할 수 있음 |
| `WEAK` | `-76 dBm` 이하 | 거리·방향·장애물 조정 권장 |
| `ACTIVE` | RSSI 로그 없이 Radar 데이터 수신 | 링크와 Radar 처리 동작 중 |

RSSI는 0에 가까울수록 강하다. `-55 dBm`이 `-75 dBm`보다 강하다.

첫 실험에서는 `Packets`가 대략 30 Hz 이상 유지되는지 확인한다. `Wi-Fi CSI link data paused`와 함께 `Samples`도 10초 이상 멈추는 상황이 반복되면 TX 전원과 배치를 점검한다.

## 6. 권장 배치

- TX-RX 거리: 약 2~5 m
- 높이: 바닥에서 약 0.8~1.2 m
- 두 보드 안테나 방향을 비슷하게 정렬
- 주 이동 동선이 TX-RX 경로를 가로지르게 설치
- 금속 표면, PC 본체, 냉장고와 벽에 밀착하지 않기
- 보정 후 보드를 움직이지 않기

Wi-Fi CSI는 원형 감지 범위를 만드는 센서가 아니다. TX-RX 직접 경로와 주변 다중경로의 변화를 감지하므로 같은 거리라도 방향, 장애물과 이동 위치에 따라 결과가 달라진다.

## 7. 데이터 수집

수집 전에 프로젝트 모니터와 공식 GUI를 닫는다.

### GUI 안내형 행동 수집

프로젝트 모니터 한 개만 실행한 상태에서 다음 순서로 수집한다.

1. 공간 프로필과 현재 채널이 맞는지 확인한다.
2. 행동 라벨을 선택한다.
3. 준비 시간과 수집 시간을 정한다.
4. `lie_down_slow`, `get_up_from_bed`처럼 시작 시점이 중요한 행동은 중간 행동 신호를 켠다.
5. `행동 수집 시작`을 누르고 준비 카운트다운 동안 자세를 잡는다.
6. 시작음 뒤 수집을 진행하고, 중간 신호가 울리면 지정 행동을 시작한다.
7. 종료 후 이번 회차가 유효했는지 선택한다.

저장 결과:

```text
data/raw/<세션-id>.jsonl
data/manifests/<세션-id>.json
data/processed/<세션-id>.md
```

manifest에는 `profileId`와 `roomId`가 함께 기록되고, 세션 ID는 사용 중인
`data/profiles/<profileId>.json`에도 연결된다. 따라서 행동 데이터는 라벨뿐
아니라 수집한 공간·배치·채널·보정 상태를 기준으로 묶어서 비교한다.

`data/` 아래의 수집 결과와 프로필은 저장소에 올라가지 않는다. 개인 환경
정보가 들어 있기 때문이며, 각자 자신의 PC에서 생성된다.

추가 행동 라벨:

| 행동 | 라벨 | 권장 수집 |
|---|---|---|
| 빠르게 앉기 | `sit_down_fast` | 20초, 10초 신호 |
| 물건 줍기 | `pick_up_object` | 20초, 10초 신호 |
| 매트리스 위 모의 낙상 | `fall_simulated_mattress` | 20초, 10초 신호 |

모의 낙상 라벨을 선택하면 별도의 안전 확인창이 나온다. 실제 바닥 낙상은
수행하지 않으며 매트리스와 보조자가 준비되지 않았으면 `Cancel`을 누른다.
안전 확인 여부는 manifest의 `safetyProtocolConfirmed`에 기록된다.

### 행동 인식용 특징 CSV 생성

반복 수집 현황을 확인하거나 모델 학습 입력을 만들 때 실행한다.

```powershell
.\.venv\Scripts\python.exe -m csi_gateway features `
  --profile-id <profileId> `
  --project-root .
```

`<profileId>`는 `data/profiles`의 파일 이름이다. 결과는
`data/processed/<profileId>-features.csv`에 저장된다. 무효로 표시한 세션과
링크 시험처럼 행동 라벨이 아닌 세션은 자동으로 제외된다.

행동당 세션이 한두 개뿐인 상태에서는 행동 분류 모델을 학습·평가하지 않는다.

### 행동 유사도 시험

같은 프로필에 기준 세션이 쌓인 행동은 새 수집이 끝날 때 실험용 예측을 표시한다.
기준 세션이 없는 라벨은 완료창에 기준 데이터가 없다고 표시된다.

1. 기준 세션을 수집한 것과 같은 프로필을 선택하고 적용한다.
2. 시험할 행동 라벨을 정답으로 선택한다.
3. 기존 예비 데이터와 맞추기 위해 수집 시간을 30초로 설정한다.
4. 정지·걷기는 30초 동안 해당 상태를 유지한다.
5. 눕기·일어나기는 중간 행동 신호를 켜고 15초에 실행한다.
6. 수집 종료 후 유효 데이터로 저장한다.
7. 완료창의 `참고 예측`이 선택한 실제 라벨과 같은지 확인한다.

수집 시작은 한 번, 중간 행동 신호는 두 번, 정상 수집 종료는 세 번의 짧은
알림음으로 구분한다. GUI를 닫아 수집이 강제로 중단된 경우에는 정상 종료음을
울리지 않는다.

예측은 현재 세션을 기준 데이터에서 제외하고 기존 행동 세션들의 특징과
거리만 비교한다. `분리도`는 가장 가까운 행동과 두 번째 행동 사이의 상대적
거리이며 확률이나 검증된 신뢰도가 아니다. 행동당 기준 세션이 한 개뿐이므로
결과가 맞거나 틀리는지 확인하는 기능 시험으로만 사용한다.

`sit_down_fast`, `pick_up_object`, `fall_simulated_mattress`는 아직 기존 기준
세션이 없으므로 완료창에 기준 데이터가 없다고 표시된다.

### 링크 설정 비교 규칙

채널이나 채널 폭을 비교할 때는 다음 조건을 고정한다.

- TX-RX 거리: 60cm의 표시된 안정 배치
- 회차당 측정 시간: 120초
- 설정별 반복: 3회
- 측정 중 보드 위치와 방향을 변경하지 않음
- 원본 JSONL과 세션 manifest를 모두 보관

설정별로 Radar sample 수, 활성 구간의 packet Hz, RSSI, 10초 이상 공백 횟수, 최장 공백, paused 시간과 active 비율을 비교한다. packet Hz는 링크 결과가 생성된 순간의 수치이므로 전체 시간의 연속성과 함께 해석해야 한다.

### GUI 자동 채널 비교

TX는 최종 배치에서 보조배터리에 연결하고 RX만 PC의 UART 포트에 연결한
상태로 실행할 수 있다.

1. 두 보드의 전원을 켜고 GUI에서 Radar 샘플이 들어오는지 확인한다.
2. `Find Best Channel (1, 6, 11)`을 누른다.
3. 약 65초 동안 방을 비우거나 완전히 정지한다.
4. GUI가 채널마다 안정화 3초, 측정 15초를 진행한다.
5. 결과 창에서 평균/최저 패킷 Hz, RSSI, 최대 Radar 공백을 확인한다.
6. 선택된 채널이 GUI의 `Current Wi-Fi channel`에 표시되는지 확인한다.
7. 이어서 `Calibrate Empty Room (40 seconds)`을 실행한다.
8. 보정 후 정지와 움직임을 다시 확인한다.

채널 비교 중 TX를 PC에 연결할 필요는 없다. 선택 채널은 PC의 공간 프로필에
저장되지만 보드 NVS에는 저장되지 않으므로 두 보드 재시작 직후에는 기본
채널 6으로 돌아간다. 이후 `공간 프로필 적용`을 누르면 저장 채널로 다시
전환할 수 있다. 전환 중 링크가 완전히 끊어지면 두 보드의 RST를 모두 눌러
채널 6으로 복구한다. 상세 설계와 제한은 [채널 보정](channel-calibration.md)을 참고한다.

현재 1·6·11은 HT20의 비중첩 채널이라는 이유만으로 고정한 것이 아니라,
빠른 설치 시험을 위한 저·중·고 대표 채널이다. HT40에서는 서로 일부
겹치며, 현재 자동 비교는 1~11 전체에서 절대 최적값을 찾는 기능은 아니다.

### 기본 검증 순서

한 배치에서 다음 상태를 각각 1분씩 최소 3회 수집한다.

1. 빈 공간
2. 사람이 앉아서 정지
3. 천천히 걷기
4. 빠르게 걷기
5. 앉기와 일어나기

움직임 감지율, 정지 오탐, 감지 지연, Radar 공백, RSSI, 패킷 빈도와 jitter 분포를 비교한다.

고정 배치 검증 후 거리, 방향, 이동 위치와 장애물을 바꿔 별도 세션을 만든다. 서로 다른 배치를 무작위로 섞지 말고 특정 배치 전체를 테스트용으로 분리한다.

낙상 모의 실험은 움직임/정지 판정이 안정된 뒤 안전 매트와 보조 인력이 준비된 상태에서만 진행한다. 고령자를 모의 낙상에 참여시키지 않는다.

## 11. 문제 해결

### COM 번호가 바뀜

정상이다. `python -m csi_gateway ports`로 다시 확인하고 명령의 포트만 바꾼다.

### COM 포트를 열 수 없음

공식 GUI, 프로젝트 모니터, 수집기 또는 `idf.py monitor` 중 하나가 이미 포트를 사용 중인지 확인한다.

### TX RGB LED가 켜지지 않음

송신 펌웨어는 RGB LED로 상태를 표시하지 않는다. 작은 빨간 전원 LED와 RX 수신값으로 판단한다.

### 정지 중에도 계속 움직임으로 표시됨

최종 배치에서 빈 공간 보정을 수행한다. 보정 후에도 반복되면 jitter, 링크 품질과 배치 조건을 기록하고 임계값 조정 전에 데이터를 먼저 수집한다.

### 움직여도 반응이 약함

TX-RX를 2~3 m로 줄이고 높이와 안테나 방향을 맞춘다. 사람의 동선이 두 보드 사이를 가로지르게 한다.

### 잠깐 결과가 멈춤

`WAITING FOR NEXT RADAR RESULT` 후 `Samples`가 다시 증가하면 일시적인 Radar 결과 공백이다. 링크 데이터와 Samples가 모두 장시간 멈추면 TX 전원과 배치를 확인한다.

## 12. 현재 구현 범위

현재 모니터는 Espressif RX 펌웨어의 보정된 `move/static` 판정을 확인하는 도구다. 다음 기능은 아직 구현되지 않았다.

- 안정적인 사람 있음/없음 판정
- 걷기·앉기·눕기 등 행동 종류 분류
- 낙상 감지
- 장시간 무활동 규칙
- 공간 프로필 이름·배치 정보 수정과 보관 프로필 복구 화면
- 선택 채널 NVS 영구 저장과 전환 실패 자동 복구
- 서버 및 Android 알림 연동
