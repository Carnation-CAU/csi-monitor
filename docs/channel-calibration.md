# 설치 채널 보정

## 현재 상태

개발용 자동 채널 비교를 2026-08-04에 구현했다. 프로젝트는 Espressif
공식 Radar 계산을 그대로 유지하며, TX/RX 채널 동기화와 프로젝트 GUI만
확장했다.

재시작 기본 채널은 6이다. GUI는 ESP-NOW 제어 신호로 두 보드를 함께
전환하고 채널 1·6·11을 비교하며 현재 채널과 선택 결과를 표시한다.
빈 공간 Radar 보정은 채널 선택 후 별도로 실행해야 한다.

## 설치 순서

1. TX/RX 위치와 안테나 방향을 최종 배치로 고정한다.
2. 동일한 채널 폭과 송신률로 후보 채널을 비교한다.
3. 한 채널을 선택하고 TX/RX를 해당 채널로 맞춘다.
4. 선택 채널을 유지한다.
5. 빈 공간 Radar 보정을 실행한다.
6. 정지·걷기 등 기본 움직임을 확인한다.

빈 공간 보정 후 채널을 바꾸면 CSI 기준선이 달라지므로 다시 보정해야 한다.

## 현재 후보 설정

- 대역: ESP32-S3 2.4GHz Wi-Fi
- 대표 기본 채널: 1, 6, 11
- 채널 폭: HT40
- TX 설정 송신률: 100Hz

1·6·11은 유일한 채널이 아니라 저·중·고 대역을 빠르게 확인하기 위한
대표값이다. 흔히 말하는 1·6·11 비중첩 구성은 20MHz 기준이다. 현재는
HT40이므로 결합된 대역이 일부 겹친다. 펌웨어는 ESP-IDF 기본 월드 세이프
설정인 1~11을 사용하며 한국 국가 프로필을 별도로 지정하지 않았다.

## 선택 우선순위

RSSI 하나만 보지 않고 다음 순서로 평가한다.

1. 10초 이상 Radar 결과 중단이 없는가
2. 최저 수신 패킷률이 높은가
3. 평균 수신 패킷률이 높은가
4. 최장 Radar 결과 공백이 짧은가
5. 반복 측정에서 결과가 안정적인가
6. RSSI는 보조 지표 또는 동률 판단에 사용

현재 15초 단회 자동 측정의 최저값은 순간 이상치에 민감하다. 향후에는
측정 시간을 늘리고 하위 10% 패킷률을 사용하도록 개선할 예정이다.

## 구현된 개발 절차

- `rf_channel`: RX의 현재 채널 조회
- `rf_channel --set 1|6|11`: TX와 RX의 동기 채널 전환 요청
- 전환 패킷 8회 반복으로 개발 환경에서 전달 안정성 보강
- 채널 1·6은 HT40 상단, 채널 11은 HT40 하단 보조 채널 사용
- GUI에서 퇴장·정지 대기 10초 제공
- 채널별 약 3초 안정화 후 15초 측정
- 최장 공백, 최저·평균 패킷률과 RSSI 비교
- 최종 채널 전환 후 빈 공간 보정 안내

## 개발 버전 제한과 복구

- 선택 채널을 NVS에 저장하지 않는다. 두 보드를 재시작하면 채널 6이다.
- 전환 확인 응답과 실패 시 자동 복귀는 아직 구현하지 않았다.
- TX/RX가 서로 다른 채널에 남으면 두 보드의 RST를 눌러 채널 6으로 복구한다.
- 자동 비교 결과의 파일 저장은 아직 GUI에 연결하지 않았다. 현재 첫 결과는
  수동으로 결과 문서에 기록했다.
- 제품화 전에는 전환 확인, NVS 저장, 시간 초과 복귀와 설치 프로필이 필요하다.

## 확인된 결과

예비 시험에서 **배치와 측정 시간이 달라지면 선택되는 채널도 달라졌다.** 짧은
거리에서 긴 시간 측정했을 때와 먼 거리에서 짧게 자동 비교했을 때의 결과가
서로 달랐다.

따라서 특정 채널을 고정 권장값으로 두지 않는다. 설치할 때마다 최종 배치에서
자동 비교를 실행하고, 그 결과를 공간 프로필에 저장해 사용한다. 측정 결과는
각자의 `data/processed`에 기록된다.
